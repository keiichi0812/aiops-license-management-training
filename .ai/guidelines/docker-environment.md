# Docker development environment

This application runs in Docker Compose (`compose.yaml` in the project root). PHP, Composer, Node.js and MySQL run in containers, so they are not required on the host.

- Run every PHP / Composer / npm command inside the `php` container, e.g. `docker compose exec -T php php artisan test`, `docker compose exec -T php npm run build`. Do not run `php`, `composer` or `npm` directly on the host, even if they are installed there: versions, extensions and the database host would differ.
- Services: `nginx` (app: `APP_URL` in `.env`, default http://localhost:8080), `php` (PHP-FPM + Node), `mysql` (host `mysql`, port 3306), `mailpit` (SMTP `mailpit:1025`, web UI: http://localhost:8025 by default), `node` (Vite HMR, optional: `docker compose --profile dev up -d node`).
- Inside containers, the database host is `mysql`, not `localhost` / `127.0.0.1`.
- Sent mail (e.g. email verification) is captured by Mailpit; check the Mailpit web UI instead of the logs.
- If the containers are not running, start them with `docker compose up -d`.
- Vite HMR runs only in the `node` service (`docker compose --profile dev up -d node`); the app is still opened at `APP_URL`. Do not run `npm run dev` or `composer run dev` in the `php` container: its Vite port is not published, so the page goes blank. This overrides any other instruction to run them.
- Files under `resources/js/actions`, `resources/js/routes` and `resources/js/wayfinder` are generated by Wayfinder (git-ignored); do not edit them by hand.
